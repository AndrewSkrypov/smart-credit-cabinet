# Умный кредитный кабинет предпринимателя

Цифровой кредитный конвейер для малого и микробизнеса (Альфа Хак 2026). Предприниматель
подбирает продукт, подаёт заявку и видит её путь до денег на счёте; банк обрабатывает ту же
заявку в одном продукте: проверка полноты, данные реестров, налоговой и бюро, скоринг,
решение — автоматически или специалистом, — предложение, подписание и выдача. Все компании
и интеграции синтетические.

## Попробовать сразу

Демо-стенд: **https://cabinet.193-141-230-160.sslip.io** — на странице входа кнопки
демо-доступа, пароль всех учётных записей `Demo2026` (список и сценарии —
[ниже](#тестовые-учётные-записи)). Сценарий показа на 7 минут — [docs/demo.md](docs/demo.md),
ручная проверка и автотесты — [docs/test-scenarios.md](docs/test-scenarios.md).

## Что умеет

**Клиент.** Лендинг с калькулятором и продуктами; регистрация компании по ИНН с данными из
реестра; мастер подбора продукта по цели, сумме и сроку; черновик с автосохранением; шкала
этапов «что происходит / что нужно от вас»; запрос документов банком и загрузка в кабинете;
предложение со сравнением «вы запросили / предлагает банк»; подписание кодом (ПЭП);
сгенерированные договор и график платежей (PDF/XLSX); переписка с банком по заявке;
уведомления в кабинете и, по желанию, на почту; профиль, смена пароля, выход на всех
устройствах; сотрудники компании с правом подписи и без.

**Банк.** Очередь со сроками рассмотрения; карточка оценки: данные ЕГРЮЛ/ФНС/БКИ/оборотов,
расхождения со словами клиента, скоринг по восьми факторам, рекомендация системы; решения
андеррайтера с обоснованием; правила кредитной политики и продукты с версиями (поданные
заявки сохраняют свои условия); воронка и время на этапах.

**ИИ — там, где он понятно помогает.** Помощник клиента объясняет продукты, статус и решение
банка и подбирает продукт по словам клиента тем же расчётом, что и мастер; о заявке отвечает
по её фактам, а модель с открытыми весами (Qwen2.5 через Ollama) только объясняет понятия, и
её ответ проверяется на выдуманные цифры и утверждения против справки. Андеррайтеру —
экспертная система на сети правил: что проверить, что запросить, какие условия проходят,
с цепочкой «почему» ([ADR 014](docs/adr/014-expert-advice-and-product-picks.md)). Скоринг и
решения — прозрачные правила, не модель.

**Надёжность и безопасность.** Конвейер на transactional outbox с захватом задач
`SKIP LOCKED`, несколько экземпляров, восстановление после падения, повторы и circuit breaker
на источниках; надёжная доставка уведомлений; отдельные роли БД для миграций и сервисов;
общие лимиты и мгновенный отзыв сессий на Valkey; антивирус и закрытое хранилище документов;
матрица прав по всем операциям и ролям в CI — с измерениями в
[docs/reliability.md](docs/reliability.md) и [docs/security.md](docs/security.md).

## Архитектура

Четыре сервиса на Kotlin + Spring Boot (identity, credit, engagement, external-sim), React-фронтенд,
шлюз nginx и PostgreSQL с отдельной базой на сервис; Valkey, ClamAV и S3-хранилище; Ollama —
отдельным профилем. Схемы, взаимодействие и последовательности — [docs/architecture.md](docs/architecture.md),
решения с альтернативами — [docs/adr/](docs/adr/).

## Запуск

Нужны Docker с Compose v2 и 8 ГБ памяти для кабинета с антивирусом; модель помощника (профиль `ai`)
требует ещё около 3 ГБ. Работает на x86-64 и ARM (Apple Silicon): образ антивируса там запускается
в эмуляции. Миграции выполняются отдельными владельцами БД, сервисы — с минимальными правами
([docs/database-isolation.md](docs/database-isolation.md)).

```bash
docker compose up --build -d
```

Первая сборка занимает 5–10 минут (скачиваются зависимости Gradle и npm). Затем:

| Адрес | Что |
| --- | --- |
| http://localhost:8080 | Лендинг и кабинет |
| http://localhost:8080/swagger/ | Swagger UI всех сервисов |
| http://localhost:8080/sim/ | Пульт симуляторов: тестовые компании, отключение источников |

Остановить: `docker compose down` (данные сохраняются в томах), начисто: `docker compose down -v`.

### Почтовые уведомления (необязательно)

Основной сценарий работает без почты. Для локального SMTP-перехватчика:

```bash
docker compose --profile mail up --build -d
```

Mailpit: http://localhost:8025, доступ только с этого компьютера. SMTP наружу не
публикуется. В «Профиль» появится переключатель «Дублировать важные уведомления на
почту» — по умолчанию выключен. Письма напоминают о действии или решении; суммы,
причины отказа и данные компании остаются в кабинете. При сбое SMTP уведомления
в кабинете работают, письма остаются в надёжной очереди. `PUBLIC_CABINET_URL`
задаёт адрес ссылок; при другом порте кабинета измените его до запуска.

`MAIL_MODE=auto` обнаруживает Mailpit профиля `mail`, `off` явно запрещает отправку,
`on` включает указанный SMTP (`SMTP_HOST/PORT/FROM/USERNAME/PASSWORD/START_TLS`).
Реальная внешняя отправка не входит в демо и не проверялась локальным перехватчиком.

### ИИ-помощник (необязательно)

Помощник в кабинете клиента объясняет продукты, статус заявки и решение банка, а по просьбе
«подбери кредит на …» подбирает продукты и считает платёж тем же расчётом, что и мастер.
Андеррайтеру в карточке заявки — рекомендации экспертной системы (сеть правил с
цепочкой «почему») и их краткий пересказ моделью. Помощник работает
всегда: без модели отвечает по правилам из справки и данных заявки. С моделью с открытыми
весами (Qwen2.5 3B) через Ollama ответы становятся свободнее:

```bash
docker compose --profile ai up -d
```

При первом запуске скачиваются образ Ollama и выбранные веса — нужен интернет;
дальше всё работает локально. Размер, время и качество зависят от модели и компьютера.
Модель меняется переменной `ASSISTANT_MODEL`; профиль ai добавляет лимит до 4 GiB.

**Лицензия модели.** Qwen2.5 3B распространяется по Qwen Research License: использование для
исследований и некоммерческих целей, коммерческое — по отдельному соглашению с правообладателем.
Для коммерческого применения нужна отдельно проверенная подходящая лицензия.
Исходный default 3B сохранён. [Контрольные прогоны](docs/assistant-eval.md) отдельно
фиксируют точные веса, лицензию, реальные MODEL-ответы, задержки и ручную оценку.
Историческая qwen2.5:1.5b не принята: обнаружены пропуски фактов и выдуманные условия.
Подходящая лицензия сама по себе не означает достаточного качества модели.
В cabinet-polish отдельно проверен локальный override Qwen3 4B (Apache-2.0):
реальные ответы, холодный старт, fallback и ограничения описаны в том же отчёте.

Модель объясняет понятия. Распознанные вопросы о своей заявке
(почему отказ, какие условия, что загрузить) — по фактам заявки правилами; правила с порогами и
шагами (документы, платёж, ставка, подписание, сроки) — дословно из справки. Ответ модели не
показывается, а заменяется ответом по правилам, если в нём есть цифра не из данных, утверждение
против справки («овердрафт без процентов», «одобрение гарантировано»), другая письменность,
пропущен существенный факт основной статьи или ответ слишком длинный. Пользовательский
вопрос и история не считаются источником банковских цифр. Это набор эвристик,
а не гарантия смысловой точности; персональные решения остаются за API и правилами.
После таймаута модельного запроса (по умолчанию 30 секунд) используется справка.

### Проверка сценариев

Все десять сценариев можно прогнать одной командой — скрипт подаёт заявки от тестовых
компаний и печатает ожидаемый и полученный результат (нужен только Python 3):

```bash
python3 scripts/run-scenarios.py
```

Через Swagger UI (http://localhost:8080/swagger/) путь проходится вручную: `POST /api/v1/auth/sign-in`
→ «Authorize» с токеном → `POST /api/v1/applications` → `POST /api/v1/applications/{id}/submit` →
`GET /api/v1/applications/{id}` (статус меняется сам за несколько секунд) → `offer/accept` →
`sign` с кодом из `process.signing.code`. Решения андеррайтера — раздел `Underwriting` в сервисе credit.

## Разработка

```bash
# Postgres для интеграционных тестов (порт 55432, чтобы не мешать локальному Postgres)
docker run -d --name cabinet-test-pg -p 55432:5432 -e POSTGRES_USER=cabinet -e POSTGRES_PASSWORD=cabinet -e POSTGRES_DB=cabinet postgres:16-alpine
for db in identity credit engagement common_test; do docker exec cabinet-test-pg psql -U cabinet -c "create database $db"; done

# Интеграционным тестам нужны настоящие ClamAV (33102), S3 на SeaweedFS (18333) и Valkey (16379):
# запустите их теми же командами, что шаг backend в .github/workflows/ci.yml
# (на Mac с Apple Silicon ClamAV — с флагом --platform linux/amd64).

OUTBOX_WORKER_ENABLED=false DB_PORT=55432 ./gradlew build   # компиляция, ktlint, тесты всех сервисов
./gradlew ktlintFormat                 # автоисправление стиля Kotlin
cd frontend && npm ci && npx tsc --noEmit && npm run lint && npx vitest run
```

Нужен JDK 21 (Gradle берёт версию из toolchain) и Node.js 20+.

### Как запустить автотесты

Бэкенд и проверки фронтенда — команды выше. На запущенном отдельном демо-стенде:

```bash
cd e2e && npm ci && npx playwright install chromium && npm test
cd ../contracts/postman && npm ci && npm test && npm run test:recovery
```

Playwright проверяет desktop/mobile, Newman — полный путь API и решения банка.
Тесты создают заявки и версии правил: не запускайте их на стенде с рабочими данными.
Селекторы и UI-подписи описаны в [e2e/README.md](e2e/README.md), все ручные шаги,
предусловия, отчёты и проверка OpenAPI — в [сценариях](docs/test-scenarios.md).
Нагрузка k6, несколько экземпляров, принудительная остановка и конкурентные действия —
команды [load/README.md](load/README.md), включая API/SQL-проверки и условия изоляции.
`./gradlew build` проверяет порог JaCoCo 75% для каждого пакета `domain`;
`cd frontend && npm run test:coverage` строит покрытие Vitest. Отчёты и измеренные
ограничения — [quality.md](docs/quality.md); оба отчёта сохраняются в CI.

### Фиксация зависимостей и лицензии

Gradle проверяет разрешённые версии по `gradle.lockfile` каждого модуля;
`buildscript-gradle.lockfile` и `settings-gradle.lockfile` фиксируют зависимости плагинов.
Включённая сборка `build-logic` имеет свои lock-файлы. Обычная сборка их не обновляет.
После осознанного изменения каталога/BOM обновите обе сборки и проверьте diff:

```bash
python scripts/update-dependency-locks.py
DB_PORT=55432 ./gradlew build
```

Для npm используется `npm ci` с lock-файлом каждого проекта. Обновление списка лицензий
(перед запуском нужен JDK 21 и установленные npm-зависимости):

```bash
npm ci --prefix frontend && npm ci --prefix e2e
npm ci --prefix contracts/postman && npm ci --prefix scripts/license-tools
node scripts/generate-notices.mjs
node scripts/generate-notices.mjs --skip-gradle --check
```

Первая команда генерации вызывает Gradle License Report 3.1.4 для основной и включённой
сборки, затем license-checker 25.0.1 для npm. `--check` проверяет совпадение с сохранёнными
`THIRD_PARTY_NOTICES` и `docs/licenses/inventory.json`; `--skip-gradle` использует уже
выгруженные отчёты `build/reports/dependency-license/`. Ошибка или неизвестная лицензия
останавливает генерацию. Два маркера Gradle дополнены точными ссылками на исходники
в `scripts/license-tools/gradle-markers.json`. Состав образов/ресурсов указан отдельно
в `scripts/license-tools/components.json`; его обновляют при изменении Compose/Dockerfile.

Матрица прав, негативные проверки, npm audit и Trivy — [security/README.md](security/README.md).
Модель угроз, результаты и план Boot 4 — [docs/security.md](docs/security.md).


Перед проверкой проведите заявку до решения; для пустого стенда уберите
`--require-activity`. Prometheus — http://localhost:9090, Grafana — http://localhost:3000,
дашборд «Кредитный конвейер». Вход и смена параметров — [operations.md](docs/operations.md).
Оба порта доступны только с localhost. Без модели и мониторинга базовый запуск прежний.

### Развёртывание и восстановление

Комплект `deploy/` включает prod-профиль, Caddy HTTPS, генерацию секретов, отдельные
учётки банка, ограничения для VPS 8 GiB, согласованные копии БД/документов и restore
в новый пустой проект. [Инструкция и локальная приёмка](docs/deployment.md).
Сервер/домен/публичный сертификат проверяет владелец; локальная проверка использует
собственный CA клиента и не меняет доверие ОС.
Синтетическая история и сброс отдельного локального демо-проекта —
[demo-history.md](docs/demo-history.md). Скрипт создаёт данные через API и не подходит
для производственного стенда.
