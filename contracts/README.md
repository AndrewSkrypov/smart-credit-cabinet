# Контракты API

Спецификации в `openapi/` выгружаются из запущенных сервисов. Аннотации контроллеров
и общая настройка OpenAPI описывают операции, русские теги, Bearer JWT, ключ
`X-Api-Key` симуляторов и ошибки. Внутренние `/internal/` скрыты; `/ext/` описан
для вызовов внутри сети, шлюз возвращает на него 404.

Из корня репозитория после запуска стенда:

```bash
python3 -m venv .venv-contracts
.venv-contracts/bin/pip install -r scripts/requirements-tools.txt
.venv-contracts/bin/python scripts/export-openapi.py
.venv-contracts/bin/python scripts/export-openapi.py --check
```

В Windows вместо `bin/python` и `bin/pip` используются `Scripts/python.exe`
и `Scripts/pip.exe`. Адрес — `CABINET_URL` или `--base-url`. В CI сравниваются
объекты YAML, порядок полей не важен. Нормализуется только автоматически
вычисленный Spring адрес в `servers`: origin зависит от HTTP-запроса экспорта.
Путь и явно объявленные в коде серверы сохраняются. Операции, схемы, примеры и правила
авторизации сохраняются и сравниваются полностью. Изменение API без обновления
снимка приводит к ошибке CI; это отдельно проверено тестом изменения ответа.

## Postman и Newman

Импортируйте `postman/cabinet.postman_collection.json` и окружение
`postman/local.postman_environment.json`. В коллекции 46 запросов: путь клиента
до выдачи и графика, загрузка PDF, повтор отправки с тем же ключом, запрос сведений,
одобрение, контрпредложение и отказ андеррайтера, версии правил и аналитика.
Каждый запрос содержит проверки. Ожидание статусов ограничено 90 секундами;
прогон в целом — пятью минутами. Начало периода аналитики берётся из серверного
HTTP-заголовка `Date`, чтобы рассинхронизация часов клиента и Docker не исключала
первые заявки из периода.

Коллекция меняет синтетические данные. Используйте отдельный демо-стенд, например
тот же `cabinet-e2e`, на котором завершились сквозные проверки. Перед запуском
убираются активные заявки задействованных демо-компаний. Не запускайте Newman
одновременно с E2E, массовым наполнением, сменой правил или остановкой сервисов.

```bash
cd contracts/postman
npm ci
npm test
npm run test:recovery
```

`CABINET_URL` меняет адрес стенда для команды `npm test`; `DEMO_PASSWORD` меняет
пароль демонстрационных аккаунтов. Секреты не сохраняются в коллекции и отчётах.
Для импорта в обычный Postman задайте адрес и пароль в своём окружении. При
запуске в Postman разрешите чтение `fixtures/synthetic.pdf` из рабочей папки
`contracts/postman`. Файл создан в проекте, содержит синтетическую надпись
и не относится к материалам организаторов.

Обёртка `run-newman.mjs` перед прогоном запоминает действующие параметры правил
и в `finally` восстанавливает их при отличии, в том числе после ошибки утверждения
и остановки Newman по `--bail`. Изменение оформляется новой версией через настоящий
API. Необратимое завершение процесса/хоста или недоступный API не дают гарантии
выполнения `finally`: в этом случае нужно восстановление по сохранённому снимку
`reports/newman-rules-before.json` или сброс отдельного демо-стенда.

`test:recovery` намеренно проваливает утверждение после записи новых правил.
Успех этой отдельной проверки означает, что отрицательный прогон вернул ошибку,
а параметры полностью восстановились новой версией. Его файлы имеют префикс
`recovery-intentional`, включая ожидаемо неуспешный JUnit; положительный результат
проверки восстановления — `reports/recovery-check.json`.

Основной JUnit — `reports/newman.xml`, снимки параметров —
`reports/newman-rules-before.json` и `reports/newman-rules-after.json`.
Коллекция и PDF воспроизводимо создаются командой
`node scripts/generate-postman.mjs` из корня репозитория.
