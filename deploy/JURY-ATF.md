# Именные QR-приглашения жюри на Dev

Маршрут `/demo/jury` использует отдельный Compose-проект `cabinet-dev-jury` с синтетическими данными. В нём восемь учёток с именными приглашениями. Страница открывает форму с именем и заполненным логином, а кнопка «Войти» обменивает одноразовый ключ на обычную сессию нужной роли. Публичный `/demo` использует свои учётки, базы и сессии.

## Подключение комплекта

Ветка `dev` должна содержать защищённый путь выпуска из MR !36. Комплект использует тот же `dev-deploy`.

1. Сгенерируйте карточки через `scripts/prepare-jury-qr.py` на машине владельца. Архив с карточками содержит действующие после активации приглашения. Файл `dev-jury-batch.json` содержит имена и хеши ключей.
2. Добавьте `dev-jury-batch.json` как защищённую GitLab-переменную типа **File** с именем `CABINET_DEV_JURY_BATCH` и областью `dev`. Передавайте файл через настройки защищённого выпуска. Имена, хеши и исходные ключи держите отдельно от Git и CI-артефактов.
3. Запустите обычный защищённый выпуск ветки `dev` с `release-images` и `dev-deploy`. Переданный комплект привязан к исходному архиву этого SHA. Если SHA уже передан на хост без комплекта, нужен свежий выпуск.
4. Дождитесь успешного `dev-deploy` и квитанции `jury_atf` с совпадающим `batch_id`, количеством `8` и сроком действия. Проверка выпуска запрашивает параметры отдельного проекта и сверяет HTTP 410 с `Cache-Control: no-store` для несуществующего приглашения. Передайте каждому участнику только его карточку. После выпуска переменную `CABINET_DEV_JURY_BATCH` можно убрать.

Срок действия рассчитывается при первой выдаче. Повтор того же выпуска сохраняет выданный срок и не восстанавливает использованные приглашения. Новый комплект выпускается после окончания предыдущего. Сбой подключения маршрута возвращает прежнюю конфигурацию Caddy.
