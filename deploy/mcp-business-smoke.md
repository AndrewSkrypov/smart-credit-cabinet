# Приёмка OAuth MCP в защищённом Dev

Контроллер вызывает `deploy/mcp_business_smoke.py` в защищённом выпуске
`cabinet-dev` под тем же `deploy.lock`, после успешного `business_smoke` и
перед свежей проверкой Alpha catchup и записью `current.json`. У модуля нет
сетевого CLI. Возвращённый `api_mcp_business_proof = PASS` относится к
хостовой API-приёмке. Браузерный статус остаётся `NOT_RUN`.

## Подключение в контроллере

При `deployment.mcp is True` сохраните результат рядом с бизнес-отчётом.
Используйте те же аргументы и дескриптор, что для `run_business_smoke`.

~~~python
from mcp_business_smoke import run as run_mcp_business_smoke

report["release"]["mcp_business_smoke"] = run_mcp_business_smoke(
    deployment, state_dir, status, desired, report, lock_fd=args.deployment_fd,
)
~~~

Существующую свежую Alpha-проверку выполните после обоих smoke. Ошибка
MCP должна попадать в обычный fail-closed обработчик контроллера до
записи `current.json`. После интеграции точка входа выпуска остаётся прежней.

~~~sh
python3 -B "$PROTECTED_RELEASE_DIR/deploy/dev-release.py" \
  --state-dir "$DEV_STATE" \
  --release-manifest "$PROTECTED_RELEASE_DIR/release.json"
~~~

Приёмка требует REMOTE для всех четырёх рантаймов, ожидаемый `current/pending`,
immutable attempt с backup и точные registry digests Credit и `cabinet-mcp`
из проверенного релиза. Публичная проверка MCP и основной бизнес-ledger
должны относиться к тому же выпуску. OAuth-клиент читается из
`deployment.values` и должен быть `alpha-hack-dev` с callback
`http://127.0.0.1:38765/callback`. Ответ с callback разбирается в памяти.
Слушатель на loopback не открывается.

## Сценарий и очистка

- Создаются две синтетические компании через signup и два временных мандата
  существующему jury AGENT. В первой заявке дважды сохраняются одинаковые
  условия с задержкой 5 и 6 дней через API веб-редактора. Это эталоны расчёта.
  После снимка состояния вызываются MCP-примерка и настоящий POST
  `/api/v1/agent/applications/{id}/financing-scenario/preview` с `mode=WEB_FORM`
  для каждой задержки. Новый WEB-маршрут разрешён только для AGENT, собственных
  тестовых заявок и без query. Совпадают точные денежные строки, обе опции,
  использованные вводные, версии и ссылка; время получения `asOf` валидируется
  отдельно. После обеих пар вызовов сравниваются версия заявки, сохранённый
  сценарий, документы и события. Дополнительно проверяются независимая
  амортизация и сумма поступления на границе. Ответ 404 нового WEB-маршрута,
  расхождение расчётов или запись после preview оставляют `INCOMPLETE`.
- Вторая заявка отправляется на рассмотрение только для проверки
  приватной выписки. После запроса банка клиент загружает синтетический
  PDF. Банк видит точные байты, AGENT получает 404 на скачивание, MCP показывает
  только состояние требования. После отзыва мандата клиента B проверяются
  существование его заявки и MCP `CASE_NOT_FOUND`. Код не принимает offer,
  не подписывает договор, не выдаёт кредит и не меняет правила или каталог.
- Первая заявка передаётся клиенту до отзыва мандата A. После отзыва клиенту
  доступен тот же пакет, а AGENT и MCP теряют доступ. Клиент отзывает известный
  ему пакет при очистке. До передачи известный агенту черновик можно отменить
  через действующий мандат. Документы, аккаунты и аудит сохраняются.
- В `finally` каждый известный access token отзывается единожды. Контрольный
  запрос с ним должен дать 401. Все запросы используют фиксированный HTTPS
  origin и общий лимит со штатным Web API, с резервом для очистки.
- Журнал `$DEV_STATE/mcp-smoke/<sha>-<uuid>.json` имеет права `0600`.
  Он содержит намерения, ID ресурсов, результаты проверок и хэши. Пароли,
  OAuth-коды, CSRF, cookies, токены, содержимое PDF и ответы API остаются в
  памяти. Неоднозначность оставляет `INCOMPLETE` и известные намерения для
  оператора. Автоповтора мутаций нет. Повторный вызов может прочитать один
  точный `PASS` этого контекста с завершённой очисткой и 401 после отзыва.
