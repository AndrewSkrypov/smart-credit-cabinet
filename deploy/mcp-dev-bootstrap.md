# Автоматическая настройка MCP на Dev

Штатный `deploy/dev-release.py` под существующим `deploy.lock` подготавливает
MCP для проекта `cabinet-dev` с каноническим `https://dev.credit-cabinet.ru` и
OCI digest MCP в проверенном manifest. Допуск версионирован в `mcp_bootstrap.py`.
OAuth регистрируется в Identity настройками `alpha-hack-dev`, `Alpha Hack Dev`
и точным redirect `http://127.0.0.1:38765/callback`.

Первый выпуск создаёт два разных случайных credentials. Один используется
между MCP и Identity, второй — между Credit и Identity при обмене кода.
Выпуск добавляет настройки к кандидатному ENV. Контроллер
сохраняет байты через enrollment и применяет их штатной заменой `cabinet.env`
после согласованной копии. Настройки Alpha и режимы runtime продолжают
действовать по прежнему состоянию и manifest.

На хосте `mcp-bootstrap` имеет права `0700` и содержит закрытый ключ CA и
запись подготовки с правами `0600`. Этот каталог исключён из монтирований
контейнеров. В `mcp-tls` с правами `0700` публикуются три каталога `0555` с
файлами `0444`. Серверные leaf имеют `serverAuth` и точные DNS SAN
`identity-mcp` и `credit`. Клиентский leaf имеет `clientAuth`. SHA-256
клиентского leaf и цепочки проверяет штатный `mcp_dev.check_tls`.

## Повтор и приёмка

- Повторяйте защищённую выкладку с тем же SHA и manifest. Если процесс прервался
  между записью подготовки, атомарной публикацией `mcp-tls` и записью ENV,
  контроллер переиспользует подтверждённые ключи и credentials. Публикация
  слоёв использует Linux `renameat2` с запретом замены занятого пути.
- Полная ручная конфигурация проверяется и используется побайтно. Явный
  `CABINET_DEV_MCP_ENABLED=false` сохраняет решение оператора. При частичной
  конфигурации или неизвестном TLS-каталоге остановка происходит до изменения
  этих данных. Содержимое ENV и приватной записи не входит в диагностику.
- MCP bootstrap выполняется только при обычной записи нового выпуска Dev.
  `verify-only`, резервирование, восстановление, Prod и изолированное демо
  используют свои штатные пути без bootstrap. Переиздание сертификатов после
  истечения срока или ротация существующих credentials требуют отдельной
  операторской процедуры. Срок leaf — 365 дней, CA — 3650 дней.
- После выкладки проверьте идентичность выпуска и штатные MCP-пробы. Они
  проверяют публичные OAuth metadata, `401` без авторизации и `404` на
  внутренних маршрутах. Сквозной OAuth smoke с синтетическими данными
  запускается отдельной защищённой проверкой.
