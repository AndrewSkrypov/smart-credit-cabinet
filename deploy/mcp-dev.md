# MCP на Dev

Обычная защищённая выкладка Dev подключает MCP только при `CABINET_DEV_MCP_ENABLED=true` в защищённом `cabinet.env`. Разрешён только проект `cabinet-dev` и origin `https://dev.credit-cabinet.ru`. При выключенной опции gateway возвращает 404 на закреплённых путях MCP и OAuth. Изолированное демо и восстановление резервных копий не включают MCP.

Перед первым включением оператор заполняет в защищённом `cabinet.env` поля `CABINET_MCP_OAUTH_CLIENT_ID`, `CABINET_MCP_OAUTH_CLIENT_NAME` и `CABINET_MCP_OAUTH_REDIRECT_URI`. Redirect браузера должен точно совпадать с зарегистрированным HTTPS адресом или числовым HTTP loopback с портом. `CABINET_MCP_IDENTITY_SERVICE_TOKEN` и `CABINET_MCP_CREDIT_SERVICE_TOKEN` содержат два разных случайных URL-safe значения. Первое получает только TS MCP и Identity, второе только Credit и Identity. Отдельный браузерный JWT не участвует в этой связи.

В каталоге `mcp-tls` рядом с `cabinet.env` хранится только TLS-материал этого окружения. Корневой каталог принадлежит оператору и имеет права 0700. Подкаталоги `identity`, `credit` и `client` имеют права 0555. В каждом нужны обычные файлы `tls.crt`, `tls.key` и `ca.crt` с правами 0444. Закрытые ключи CA остаются отдельно. Права 0444 нужны непривилегированным процессам внутри контейнеров. На хосте чтение ограничивает родительский 0700. Используются цепочки, проверяемые соответствующим `ca.crt`, и незашифрованные ключи leaf для запуска сервисов. У серверных leaf нужны EKU serverAuth и DNS SAN `identity-mcp` или `credit` соответственно. У клиентского leaf нужен EKU clientAuth. Контроллер проверяет цепочки, имена и пары ключей и рассчитывает SHA-256 клиентского leaf. Замена выполняется под существующим lock Dev и должна пройти проверку нового набора перед открытием HTTPS.

Gateway и MCP используют отдельную внутреннюю сеть на HTTP, внешнее TLS завершает Caddy. Credit, MCP и TLS-адаптер Identity подключены только к их внутренней сети транспорта. Адаптер передаёт два точных POST запроса на Identity по отдельной внутренней сети. Caddy остаётся единственным сервисом MCP-маршрута с опубликованными портами. Образ `cabinet-mcp` берётся по digest из `release.json`; используются обычные проверка provenance и rollout.

До открытия Caddy проверяются TLS-цепочки и имена обоих внутренних адресов, обязательный клиентский сертификат Credit, отказы без scoped данных и недоступность обычного actuator через адаптер. Штатная публичная проверка сверяет метаданные, запрос к MCP без доступа и закрытые частные маршруты. Полная приёмка дополнительно проверяет синтетический OAuth/PKCE, вызовы MCP и неизменность данных Credit.

Для обычного отключения оператор переводит флаг в false в закрытом файле и запускает контроллер выпуска под тем же lock. Он исключает overlay, закрывает маршруты и удаляет только два stateless MCP-контейнера ранее проверенного Dev. Прямое переключение во время незавершённого выпуска не заменяет действующую процедуру recovery и резервной копии. Базы и постоянные тома Dev сохраняются.
