# 001. Кредитный процесс в одном сервисе

Статус: принято; отражает текущую реализацию.

**Контекст.** Отправка, проверка, решение, предложение и выдача меняют одну заявку.
После каждого перехода нужны согласованные журнал и следующая задача.

**Решение.** Оставить `application`, `pipeline`, `assessment`, `decision`, `offer`
и `document` модулями одного `credit`. Границы домена и внешних адаптеров задаются портами;
данные принадлежат базе `credit`.

**Альтернативы.** Разделить этапы на сервисы с брокером и согласованием событий;
собрать весь кабинет в один монолит. Первый вариант добавляет распределённые отказы,
второй связывает независимые identity и engagement с кредитным процессом.

**Последствия.** Переход, событие и постановка задачи входят в одну транзакцию.
Сервис развёртывается и масштабируется целиком; независимо масштабировать скоринг нельзя.
Выделение модуля потребует отдельного контракта и проверки повторной доставки.

Основание: [архитектура](../architecture.md), `services/credit/src/main/kotlin/ru/creditcabinet/`.
