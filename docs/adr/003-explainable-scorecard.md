# 003. Объяснимая балльная карта

Статус: принято; отражает текущую реализацию.

**Контекст.** Нужны воспроизводимые причины отказа и возможность показать, какие факторы
дали рейтинг. Размеченной выборки реальных кредитных исходов у прототипа нет.

**Решение.** `Scorecard` и `CreditPolicy` — чистые функции: стоп-факторы, баллы, рейтинг,
проверка нагрузки и параметров продукта. Результат сохраняет входы, разложение баллов
и версию `rule_sets`. Риск-администратор публикует новую версию параметров.

**Альтернативы.** Обученная ML-модель, внешнее решение БКИ, решение языковой модели.
Без выборки невозможно подтвердить качество ML; внешняя система недоступна на обычном ПК;
свободный текст модели не даёт требуемой детерминированности финансового решения.

**Последствия.** Решение можно объяснить и покрыть тестами без сети. Правила синтетические:
они не доказывают качество реального кредитного риска и требуют калибровки перед реальным
применением. Старые версии сохраняются приложением; отдельного запрета UPDATE на уровне
БД для правил и решений нет.

Основание: `assessment/domain/Scorecard.kt`, `assessment/domain/CreditPolicy.kt`,
[модель процесса](../process-model.md).
