# 014. Экспертная система МИВАР для андеррайтера и подбор продукта в помощнике

Статус: принято; отражает текущую реализацию.

**Контекст.** Андеррайтеру на ручном рассмотрении нужно быстро понять, что мешает решению:
что проверить, что запросить у клиента, какие условия проходят по политике. Языковая модель
для этого не годится как источник выводов: она может выдумать цифру или условие, а вывод
должен быть воспроизводимым и объяснимым. Клиент, в свою очередь, просит помощника
«подобрать кредит» — ответ должен опираться на те же продукты и расчёты, что и мастер подбора.

**Решение.**
- В `credit` (модуль `advice`) — экспертная система по подходу МИВАР: модель из параметров и
  правил (двудольный граф «параметр — правило»), прямой логический вывод от известных фактов,
  каждое правило срабатывает один раз, когда известны все его входы; у каждого параметра один
  источник, поэтому результат не зависит от порядка правил. Для каждого совета хранится цепочка
  сработавших правил со значениями — это и есть объяснение «почему». База знаний
  `UnderwritingAdviceModel` (версия в ответе) выводит из заявки, данных ЕГРЮЛ/ФНС/БКИ/банка,
  автоматического решения и набора правил: нагрузку с новым платежом, срок или сумму в пределах
  порога, расхождение выручки, нестабильность оборотов, частые запросы в бюро, погашенную
  просрочку, недоимку, возраст бизнеса, отраслевой риск. `GET /api/v1/underwriting/applications/{id}/advice`
  — только сотрудникам банка.
- Система советует, но не решает: рекомендация решения по-прежнему выдаёт скоринг, а решение
  принимает специалист.
- `POST /api/v1/assistant/underwriting-summary` (engagement, только сотрудники банка): модель с
  открытыми весами пересказывает выводы системы в трёх–четырёх предложениях; цифра не из выводов
  или отсутствие модели дают сводку по правилам.
- Подбор в помощнике: цель, сумма и срок извлекаются из вопроса правилами, продукты и платежи —
  тем же `POST /api/v1/products/match`, что и в мастере; ответ — по правилам, без модели.
  Кнопка «Оформить» открывает мастер с заполненными полями. Вопрос на сравнение продуктов
  («что лучше: овердрафт или кредит?») по-прежнему объясняет модель по справке.

**Альтернативы.** Настольный редактор KESMI (МИВАР) — Qt-приложение без серверного API,
его нельзя вызвать из сервисов; модели в нём можно проектировать. Серверный вычислитель
МИВАР по лицензии банка подключается вторым адаптером за тем же контрактом совета без изменения
интерфейса. Ответы модели вместо правил — невоспроизводимы и не объясняются цепочкой.

**Последствия.** Изменение правил андеррайтинга — изменение кода с тестами и повышение версии
модели. Пороги политики (нагрузка, расхождение выручки) берутся из версии набора правил, по
которой принималось автоматическое решение. Подбор в помощнике понимает типичные формулировки;
непонятый запрос получает уточняющий вопрос, а не догадку.

Основание: `services/credit/src/main/kotlin/ru/creditcabinet/advice/`,
`services/engagement/src/main/kotlin/ru/creditcabinet/assistant/ProductPicker.kt`.
