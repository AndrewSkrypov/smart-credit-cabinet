# Страницы заявок

`GET /api/v1/applications/page` — дополнительный read API. Старый массив
`GET /api/v1/applications` сохранён для прежних потребителей.

Параметры: page с нуля, size 1..100 (default 20), q до 100 символов после trim,
sort: default/oldest/newest/number_asc/number_desc. Неизвестные группы/сортировки,
отрицательные страницы и переполнение offset возвращают 400.

Группы банка: review (MANUAL_REVIEW), client (INFO_REQUESTED/OFFER_ISSUED/SIGNING),
system (SUBMITTED/ENRICHMENT/SCORING/DISBURSING), done (DISBURSED/REJECTED/WITHDRAWN/CLOSED).
Группы клиента: active (все незавершённые), done, action
(DRAFT/INFO_REQUESTED/OFFER_ISSUED, также SIGNING при canSign).
action пересекается с active: суммировать эти счётчики нельзя.

Клиент ограничен своей компанией; банк не видит DRAFT. Права применяются в SQL
до поиска, count, limit и материализации сущностей. Поиск подстроковый:
номер/компания/ИНН для банка, номер/сохранённое название продукта для клиента.
Символы %, _ и ! считаются буквальными, параметры связаны через JDBC.

Ответ содержит items, page, size, totalElements, totalPages, hasNext,
countsByGroup, actionRequiredCount, actionRequiredPreview.
countsByGroup применяет текущий поиск ко всей доступной области до пагинации.
Клиентское action-превью глобально по компании, независимо от поиска и страницы,
ограничено пятью записями. На UI это подписано явно. Для банка превью пусто.
Пустой результат: page=0, totalPages=0. Слишком глубокая допустимая страница
возвращает последнюю существующую. unreadChatCount считается только для
ограниченного набора items/preview.

Default: банк по statusChangedAt ASC, done DESC; клиент по createdAt DESC.
oldest/newest используют statusChangedAt; number_* — номер. У всех есть
уникальный ID в том же направлении как tie-breaker.
Внутри одного запроса используется REPEATABLE READ. Между offset-запросами
snapshot-гарантии при конкурентных изменениях нет. Cursor API — следующий этап.

UI банка запрашивает 20/50/100 строк, клиент — 10 карточек. Параметры в URL,
поиск с debounce 300 мс. Polling ограничен текущим запросом, без наложения,
при скрытой вкладке приостановлен. Поздние ответы старой выборки игнорируются;
ошибка сохраняет видимый список. Фоновые изменения применяются кнопкой
«Показать обновления»; ответ A после буфера B очищает B. Возврат из карточки
восстанавливает URL и позицию из ограниченного кэша текущего пользователя.

Проверка SQL: ApplicationPagesIntegrationTest — реальная PostgreSQL, 1001 запись
с одинаковыми датами и фиксированными номерами/ID, права, поиск за первой
страницей, буквальные подстроки, clamp, Hibernate entityLoadCount и EXPLAIN Limit.
Новая миграция не потребовалась: проверенный план ограничивает выдачу до
материализации. Это не нагрузочное доказательство для произвольного объёма.

Превью сотрудников ограничено пятью на UI; DTO компании пока содержит полный
массив. Серверная пагинация сотрудников, событий, документов, аудита чата и
метаданных версий остаётся отдельным этапом.
