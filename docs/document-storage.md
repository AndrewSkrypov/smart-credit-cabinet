# Документы: local, S3 и антивирус

По умолчанию новые документы сохраняются в `cabinet-documents`. ClamAV проверяет
и обычные файлы, и вложения чата. Его недоступность закрывает новые загрузки, но
не мешает читать уже сохранённые файлы. Порт скачивания и проверка прав заявки едины
для обоих хранилищ; адрес S3 не передаётся браузеру.

## Выбор хранилища

Для S3 в PowerShell:

```powershell
$env:STORAGE_BACKEND='s3'
docker compose --profile storage up -d --build
```

В POSIX shell:

```sh
STORAGE_BACKEND=s3 docker compose --profile storage up -d --build
```

Переключение `STORAGE_BACKEND` влияет только на новые файлы. `storage_backend` в каждой
строке `documents` определяет чтение прежних файлов. Если в БД остались строки `S3`,
SeaweedFS должен работать и при `STORAGE_BACKEND=local`; профиль `storage` сохраняется.
Нельзя удалять старый локальный том после переключения переменной.

| Переменная | Значение демо по умолчанию | Назначение |
| --- | --- | --- |
| `STORAGE_BACKEND` | `local` | Новые записи: `local` или `s3` |
| `STORAGE_ENABLED` | `false` | Для deploy: сохранить профиль S3 при записи в local; `s3` включает его автоматически |
| `S3_ENDPOINT` | `http://seaweedfs:8333` | Внутренний адрес, path-style |
| `S3_REGION` | `us-east-1` | Регион подписи запросов |
| `S3_BUCKET` | `cabinet-documents` | Отдельный бакет |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Синтетические ключи демо | Ограниченная учётная запись credit |
| `S3_ADMIN_ACCESS_KEY`, `S3_ADMIN_SECRET_KEY` | Синтетические ключи демо | Отдельная учётная запись оператора |
| `DOCUMENT_UPLOADS_ENABLED` | `true` | При `false` новые загрузки получают 503 |
| `ANTIVIRUS_TIMEOUT` | `PT10S` | Общий дедлайн VERSION и INSTREAM |
| `ANTIVIRUS_MAX_SIGNATURE_AGE` | `PT72H` | Максимальный возраст сигнатур |

Внешние ключи не помещают в Git, команды общего журнала или отчёты. Демо-значения
не предназначены для внешнего размещения. JSON ключей SeaweedFS создаётся внутри
контейнера с правами 0600; он не находится в томе данных и не должен попадать в архивы.

## Сигнатуры и отказы

```sh
docker compose exec clamav clamdscan --version
docker compose logs --tail 50 clamav
docker compose ps
```

`VERSION` показывает версию загруженной базы, а не только установленного пакета.
Healthcheck проверяет эту дату по тому же `ANTIVIRUS_MAX_SIGNATURE_AGE`, что и credit
(целые дни/часы/минуты/секунды ISO-8601, например `P3D` или `PT72H`). Один `PONG`
не означает готовность к загрузкам. При первом старте freshclam может обновить файлы
до появления сокета clamd. Если версия на диске новее загруженной, healthcheck запрашивает
`RELOAD` и остаётся отрицательным до фактического переключения движка; повторный запрос
ограничен одним в минуту. Это также покрывает обновление во время первоначальной загрузки,
которое может не заметить `SelfCheck`. Дополнительно установлен `SelfCheck 30`.
Перезагрузка базы последовательная: два движка одновременно не помещаются в бюджет
2 GiB. На время перезагрузки возможен ограниченный 503; недосканированный файл не сохраняется.
При устаревшей базе проверить сеть `freshclam`, место в томе `cabinet-clamav-signatures`
и время UTC. После обновления дождаться загрузки базы в `clamd`. Увеличивать допустимый
возраст вместо восстановления обновлений не следует. Недоступность, неполная проверка
и неизвестный ответ дают русское сообщение «Проверка файлов временно недоступна».

При отказе S3 чтение локальных документов продолжается. Новые S3-загрузки получают 503;
переключение записи в local — отдельное решение оператора, без автоматического fallback.
`healthy` контейнера и успешная загрузка через обе реплики — разные проверки:

```sh
python load/storage.py --project cabinet-e2e --base http://localhost:8080
```

Команда допускает только локальный демо-стенд с двумя credit, включённым S3 и ClamAV.
Она останавливает и запускает эти sidecar-сервисы, проверяет 503 для двух видов загрузок
на обеих репликах, неизменность БД при отказе и точные байты после восстановления.
Результат содержит фактические задержки и успешность в `load/reports/storage/verified.json`.

## Сохранность и перенос

`cabinet-seaweedfs` содержит и метаданные, и объектные данные `/data`. Его согласованная
копия требует остановки всех writers, затем SeaweedFS. Отдельный архив старого локального
тома обязателен, пока есть документы `LOCAL`. V8 не заполняет прежние SHA-256 без чтения
файлов; хэш заполняется только после проверки фактических байтов.

Установите закреплённые зависимости оператора в отдельное Python-окружение:

```sh
python -m pip install -r scripts/requirements-storage.txt
python deploy/storage_transfer.py --project cabinet-prod --target s3 --report inventory.json
python deploy/storage_transfer.py --project cabinet-prod --target s3 --apply --report transfer.json
```

Без `--apply` команда только читает объекты и метаданные. При выполнении она берёт общую
с backup блокировку PostgreSQL, останавливает все работающие credit, проверяет размер и
SHA-256 каждого исходника, копирует недостающие объекты и сверяет байты чтением из назначения.
Метаданные всех документов меняются одной транзакцией только после всех проверок. Включены
прежние документы, удалённые из UI записи и вложения чата. Исходные копии не удаляются.
Существующий целевой файл с другими байтами останавливает перенос; он не перезаписывается.

Файл отчёта должен быть новым. Он содержит UUID, размеры, хэши и этапы, без имён файлов
пользователя, токенов и ключей. Храните его закрыто. После обрыва процесса:

```sh
python deploy/storage_transfer.py --project cabinet-prod --target s3 --apply --resume-report transfer.json --report resumed.json
```

Повторная команда проверяет уже скопированные объекты. `--resume-report` также восстанавливает
исходное состояние writers, оставшихся остановленными после аварийного завершения процесса;
состав контейнеров должен совпасть. После успешного переноса скрипт ждёт их `healthy`.
Проверяйте скачивание через API отдельно: успешный старт контейнера его не заменяет.

Обратный перенос использует `--target local` с теми же проверками. Сначала переключите новые
записи в local, оставляя SeaweedFS включённым (`STORAGE_ENABLED=true` для deploy), затем выполните
обратный перенос. Пока существуют строки `S3`, отключать SeaweedFS нельзя. Новые файлы,
появившиеся после первого переключения, также должны пройти обратное копирование.

Приёмка на локальном синтетическом стенде с двумя credit:

```sh
python load/storage-transfer.py --project cabinet-e2e --base http://localhost:8080
```

Проверяются принудительный обрыв процесса, неизменность БД, возобновление, повтор без копирования,
конфликтующая копия, обратный перенос и API обычных документов/вложений с правами владельца,
банка и чужой компании. Отчёт — `load/reports/storage-transfer/verified.json`.

`deploy/backup.py` создаёт формат 2: три дампа, архив local и, если том существует, архив
всего `/data` SeaweedFS после остановки записи и хранилища. При наличии строк `S3` отсутствие
этого тома блокирует копию. Restore принимает прежний local-формат 1 и новый формат 2,
проверяет оба архива до извлечения и требует пустой отдельный проект. Для восстановления S3
создавайте настройки через `deploy/configure.py --storage s3`. Подробности и ограничения —
[развёртывание](deployment.md). Локальная приёмка прошла на двух отдельных наборах по
20 компаний: S3/формат 2 и local/прежний формат 1. Проверены выдача, все таблицы и
последовательности, байты томов, обычный PDF и вложение чата через восстановленный API.
Пик наблюдаемой памяти — 2669,9 MiB для S3 и 2549,4 MiB для local; это контейнерные
измерения на машине с запасом RAM, не испытание отдельного VPS 8 GiB. Результаты,
версии образов и оставшиеся проверки — [в отчёте](security-results/document-storage.json).
Само переключение env не является проверенным восстановлением.
