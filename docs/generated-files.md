# Файлы условий и графика платежей

До выдачи кредита кабинет предлагает предварительный график в PDF и XLSX. После
выдачи доступны три окончательных файла: PDF условий, PDF графика и XLSX графика.
Генерируемые файлы показаны отдельно от документов, которые компания загружает банку.
Они не закрывают запрос на недостающие документы.

PDF оформлен как компактный банковский бланк: реквизиты заявки и заёмщика, разделы,
таблица платежей, номер заявки и страницы в колонтитулах. Кириллица обеспечивается
встроенными DejaVu Sans. Лицензия поставляется
[вместе со шрифтами](../services/credit/src/main/resources/fonts/LICENSE-DejaVu.txt)
и отражена в [реестре компонентов](licenses/inventory.json).

## Содержание

- «Кредитный договор — демонстрационная копия» содержит сохранённый перед подписанием
  текст без замены текущей редакцией продукта или правил. Контрольная сумма SHA-256
  относится к этому тексту. Сведения о синтетическом подписании находятся отдельно.
- Историческая заявка без исходного текста получает «Сводку сохранённых условий».
  В ней прямо указано отсутствие подписанного оригинала; хеш исходного текста не создаётся.
- График использует сохранённые сумму, срок, ставку и тип кредита. Платежи и итоговые
  суммы совпадают с серверным LoanMath. Для лимита явно указано допущение полного
  использования. Сервер определяет номера месяцев, поэтому календарные даты не выдумываются.
- XLSX содержит числовые значения всех платежей, закреплённую строку заголовков,
  фильтр, числовые форматы и настройки печати. Это снимок расчёта, а не новая финансовая модель.

Все документы и операции подписания демонстрационные. Реальные кредиты не выдаются.

## Доступ и восстановление

`GET /api/v1/applications/{id}/artifacts` возвращает метаданные и состояния
`PENDING`, `READY`, `ERROR`. Ссылка скачивания появляется только для `READY`.
`GET /api/v1/applications/{id}/artifacts/{artifactId}/download` требует bearer-токен;
интерфейс скачивает файл авторизованным запросом. Обычная внешняя ссылка на S3 не используется.
Доступ разрешён представителям компании и сотрудникам банка в пределах просмотра заявки.
Чужая компания получает 404, отозванная сессия — 401 на шлюзе.

`POST /api/v1/applications/{id}/artifacts/{artifactId}/retry` повторяет создание
неподготовленного файла. Для готового файла возвращается тот же результат. Реестр
`generated_artifacts` хранит неизменный вход, его хеш, версию шаблона, фазу, тип,
размер, контрольную сумму и расположение. Повторы сохраняют ID и ключ объекта.
Исходный backend сохраняется и после изменения режима новых записей LOCAL/S3.

Генерация работает в отдельном ограниченном worker. Она не входит в транзакцию выдачи.
Конкурирующие экземпляры используют блокировки строк; незавершённая запись не становится
`READY`. Автоматические попытки ограничены пятью; пользователь может запустить повтор.
Скачивание проверяет размер и SHA-256. Недоступный или повреждённый объект возвращает
503 и переводит запись в ошибку для повторного создания из сохранённого входа.

Оператор [переноса LOCAL/S3](../deploy/storage_transfer.py) включает готовые файлы
из обоих реестров. Backup учитывает backend генерируемых файлов, включая случай,
когда загруженные клиентом документы находятся только в LOCAL. Прежние объекты
при переносе сохраняются; отличающаяся целевая копия не перезаписывается автоматически.

## Почта

После сохранения всех трёх окончательных файлов credit ставит отдельное событие
«Документы по кредиту готовы» в durable outbox. Заявка и файлы остаются доступны
при отказе SMTP. Письмо о выдаче сообщает о зачислении; письмо о файлах сообщает
только о возможности скачать подготовленные документы. Оба ведут в кабинет.

При доставке и повторе проверяются текущая подписка, активность сотрудника и актуальный
email. В письме нет вложений, внутренних ключей хранилища, сумм, скоринга или токенов.
Событие готовности и постановка в очередь дедуплицируются, Message-ID устойчив к повтору.
Exactly-once SMTP не обещается. Завершённое задание outbox также может означать
подавление из-за отписки или отзыва доступа; это не доказательство доставки письма.

## Проверка на отдельном стенде

Следующие команды изменяют только синтетические данные явно указанного локального
Compose-проекта. Нужны работающий mail-профиль и Mailpit; реальные SMTP запрещены.

```bash
python load/generated-files.py --project cabinet-e2e --base http://localhost:8080 --mailpit http://127.0.0.1:8025 --report-name generated-files
```

Проверка создаёт компанию и сотрудников, останавливает собственный Mailpit, выдаёт
синтетический кредит, скачивает три файла, меняет email, отзывает одного сотрудника
и отключает почту другому. После рестарта отправителя и восстановления SMTP проверяет
одно фактическое письмо на новый адрес, отсутствие писем подавленным получателям
и устойчивый Message-ID. Mailpit восстанавливается в `finally`.

Для S3 сначала включают собственный storage-профиль и backend S3, затем выполняют ту же
проверку. Идентификатор выданной заявки из её отчёта передают дополнительной проверке:

```bash
python load/generated-storage.py --project cabinet-e2e --base http://localhost:8080 --application UUID_ИЗ_ОТЧЁТА --report-name generated-storage
```

Она проверяет отказ скачивания, выдачу следующего кредита при недоступном S3,
состояния ошибки и восстановление всех файлов с прежними ID/ключами. S3 запускается
обратно в `finally`. JSON-отчёты находятся в `load/reports/<report-name>/verified.json`;
значение `passed` проверяется явно. Эти проверки дополняют общие storage/restore,
security и сквозные проверки, а не заменяют их.
