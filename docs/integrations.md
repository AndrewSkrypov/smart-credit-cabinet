# Интеграции и симуляторы

Кабинет не обращается к корпоративным системам и платным сервисам: все внешние источники
работают локально в сервисе `external-sim` на синтетических данных. Контракты упрощены, но
сохраняют смысл интеграции: запрос по ИНН, ответ с полями, которые реально используются в
правилах (`docs/process-model.md`), авторизация вызывающей системы, отказы и задержки.

## Как устроено

| Что | Где |
| --- | --- |
| API симуляторов | `http://external-sim:8080/ext/...` — только внутри сети compose, шлюз отвечает на `/ext/` 404 |
| Авторизация | Заголовок `X-Api-Key` (переменная `SIM_API_KEY`): систему вызывают сервисы банка, а не пользователи |
| Пульт для демо | `http://localhost:8080/sim/` — тестовые компании и переключатели «работает / медленно / недоступен» |
| Документация API | Swagger UI → `external-sim` |
| Данные | `services/external-sim/src/main/resources/dataset/companies.json` |

Каждый ответ занимает реалистичное время (`SIM_LATENCY_MS`, по умолчанию 200 мс). Режим
«медленно» отвечает через `SIM_SLOW_DELAY_MS` (8 с) — дольше, чем ждёт клиент; «недоступен» —
сразу 503. Так на живом стенде видно, что конвейер повторяет запрос, а заявка ждёт, а не падает.

## Источники

| Система | Реальный аналог | Метод | Что отдаёт | Кто вызывает |
| --- | --- | --- | --- | --- |
| Реестр | ЕГРЮЛ / ЕГРИП (ФНС) | `GET /ext/registry/v1/companies/{inn}` | ОГРН, наименование, статус (действует / ликвидация / банкротство / исключено), дата регистрации, ОКВЭД, руководитель, учредители, адрес, признаки недостоверности | identity — при регистрации; credit — при обогащении |
| ФНС | Сервис «Прозрачный бизнес» | `GET /ext/fns/v1/companies/{inn}/summary` | Выручка и расходы за прошлый год, уплаченные налоги, недоимка, численность, режим налогообложения, массовый адрес; `hasReports=false`, если отчётности ещё нет | credit |
| Бюро кредитных историй | БКИ | `GET /ext/bureau/v1/reports/{inn}` + `X-Consent-Id` | Действующие обязательства (лимит, остаток, платёж, текущая просрочка), худшая просрочка за 24 мес, запросы за 30 дней. Без согласия — 400 | credit |
| Данные банка | АБС / хранилище данных банка | `GET /ext/bank/v1/clients/{inn}` | Есть ли счёт в банке, обороты по счёту за 12 мес | credit |
| Подписание | Сервис простой электронной подписи (ПЭП) | `POST /ext/signing/v1/sessions`, `POST .../{id}/confirm` | Одноразовый код (6 цифр, 5 минут, 5 попыток), подпись, привязанная к хэшу документа | credit |
| Выдача | АБС | `POST /ext/core/v1/loans` | Номер договора, ссудный и расчётный счета, дата выдачи и погашения; повтор по той же заявке возвращает тот же кредит | credit |

**Почему код подписи возвращается в ответе.** Настоящая ПЭП присылает код по SMS, но условия
кейса запрещают SMS в сценарии. Сервис подписания отдаёт код вызывающей системе, а кабинет
показывает его пользователю — шаг подтверждения при этом остаётся.

## Синтетические компании

ИНН начинаются с `00`: региона с таким кодом нет, поэтому данные никогда не описывают реальный
бизнес. Для любого другого корректного ИНН с префиксом `00` симулятор генерирует типичную
здоровую компанию — всегда одну и ту же для одного номера. Реальные ИНН реестру неизвестны (404).

Расчёт баллов — по балльной карте из `docs/process-model.md` (раздел 6) для заявки из последнего
столбца; заявленная выручка совпадает с данными ФНС.
