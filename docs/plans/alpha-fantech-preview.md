# Фантех: примерка и MCP

Общий исходник собран в `feature/fantech-dev-release` от защищённого
`477588b7be2525a0417087e0adf623315d282a91`. В него входят примерка
`c8978188d25e13a95fce87c50be4df864d262125` и MCP из MR !31
`2d4b395b7595b482da27f8796439756b3bd88cd9` с проверками интеграции.
Документ описывает исходник и локальную приёмку. Выкладка этого среза на Dev
подтверждается отдельно фактическими CI, manifest и отчётом стенда.

## Разделение операций

| Клиент | Операция | Допуск |
| --- | --- | --- |
| Веб-кабинет | `POST /api/v1/agent/applications/{id}/financing-scenario/preview` | Обычная авторизация агента; `WEB_FORM` использует параметры формы, `SAVED_SCENARIO` — сохранённый сценарий |
| Локальный MCP | `POST /api/v1/agent/mcp/applications/{id}/financing-scenario/preview` | Только `agent-mcp-local`, IPv4 loopback и `SAVED_SCENARIO` |
| Удалённый MCP | `POST /internal/mcp/credit/applications/{id}/financing-scenario/preview` | Частный TLS-коннектор, доверенный peer, проверяемый Identity actor assertion и `SAVED_SCENARIO` |

Локальный адаптер использует свой префикс `mcp/`. Его преобразование в
частный путь удалённого адаптера сохраняет прежний internal URL. Профиль MCP
не выключает веб-примерку и не создаёт второй обработчик её URL.

Все варианты используют `FinancingScenarioCalculation.calculate` и `LoanMath`.
Обёртка `draft` сохраняет контракт сохранённого MCP-сценария. Денежные значения
предварительного расчёта передаются строками. MCP DTO с текстовым номером
заявки сохранён независимо от веб-моделей.

Расчёт не сохраняет заявку или пакет, не загружает PDF, не добавляет журнал
и outbox. Сохранение выбранного варианта выполняется отдельно в вебе.
Смена компании, пользователя, условий заявки или версии каталога скрывает
устаревший ответ в интерфейсе. Сохранённый расчёт с несовпадающей версией
заявки и каталога отклоняется. Отзыв мандата закрывает доступ агента.

## Контракты и проверенные условия

| Условие | Локальное подтверждение |
| --- | --- |
| Задержки 5 и 6 дней дают разные остатки по одной формуле | PostgreSQL сценарии и вызовы Node MCP к Credit |
| Пробный расчёт не меняет сохранённые данные | Сверка версии, сценария, документов, журнала и outbox до и после |
| Изменившаяся версия каталога не используется молча | Отдельная фикстура с двумя действительными версиями продукта и ответом `409` |
| Веб и локальный MCP доступны вместе | Запуск `agent-mcp-local`, разные URL, оба расчёта проверены |
| Частные MCP URL не попадают в публичный Swagger | Контексты по умолчанию и `agent-mcp-remote`, `@Hidden` на частном контроллере |
| Публичная матрица совпадает с фактическим контрактом | 88 операций Credit, 134 операции четырёх REST-сервисов и 134 строки матрицы |

На исходнике `869e25b9468e7c04084e075042a20c34a5569bab` прошли 12 целевых
тестов Credit без ошибок и пропусков. Среди них — реальный HTTP к Credit
через Node MCP, сценарии версий и прав, а также проверки публичного контракта.
Проверка remote-контекста использует MockMvc и транспортные моки: она
подтверждает маршрутизацию и Swagger, а живая приёмка TLS/OAuth выполняется
отдельно после развёртывания.

После обновления `follow-redirects` прошли все 208 тестов фронтенда в
39 файлах, ESLint, TypeScript, Vite и typecheck E2E. Исторические результаты
и текущие локальные проверки не подменяют новую приёмку GitLab и Dev.

## Проверка после выкладки

1. Сверить точные SHA и manifest, четыре удалённых runtime, здоровье и отсутствие pending.
2. В вебе изменить задержку 5 → 6 → 5, проверить объяснение и перезагрузить заявку:
   пробные расчёты не сохраняются, выбранный вариант сохраняется только явно.
3. Повторить четыре бизнес-сценария, включая приватную выписку и резерв.
4. Подключить внешний MCP через OAuth на синтетике, сверить его деньги с
   веб-примеркой и проверить отзыв полномочий. Зафиксировать версии обеих сторон.
