# Alpha. Приёмка гексагонального пилота

[План](alpha-hexagonal-refactor.md) · [Реестр исполнения](alpha-hexagonal-execution.md)

Проверки ниже относятся к одному интегрированному кандидату. Исходные статусы берутся из `JdbcAnalyticsQueries`, роли — из `AnalyticsQuery` и `CurrentCaller`. Доказательства привязываются к полному SHA, окружению, команде, статусу и артефакту. Когда результат меняется, сохраняется ссылка на прежнюю попытку.

## Условия завершения

Теневой этап закрывается после A01–A08, A10–A13 на кандидате в доступной изолированной среде. A09 и целевые доказательства A11 закрывают допуск к переключению на dev. Для проверки текущего API при выключенном флаге используется часть A09. Точное значение допустимого отставания согласуется по измерению теневого прогона и фиксируется до переключения.

По каждому ID реестр хранит `ожидает`, `в работе`, `пройдено`, `не пройдено` или `заблокировано`. Проверка инфраструктуры и успешная компиляция подтверждают только свои строки. При частичной готовности указываются открытые критерии и условия продолжения.
