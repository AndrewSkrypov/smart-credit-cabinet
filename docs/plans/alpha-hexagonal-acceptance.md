### Наборы для A03

- Проверить карточку, очередь, счётчики и чат банка через `BankSubmissionVisibilityIntegrationTest`. Банковская видимость определяется фактом `submitted_at`. `currentStatuses` учитывает все поданные заявки, включая заявки вне выбранного периода. Период применяется к историческим показателям воронки.
- Проверить старую агентскую заявку после обновления до V21. Первая передача восстанавливается по событию `REQUEST_CLIENT_CONFIRMATION`. Если события нет, миграция берёт `submitted_at` у поданной заявки или `status_changed_at` у заявки в `PENDING_CLIENT_CONFIRMATION`. Эти признаки определяют доступ своего клиента к заявке. Банку по-прежнему нужен `submitted_at`, в том числе при терминальном статусе.
- Сверить решение о чтении проекции через `HttpCurrentStatusesProjectionTest`. Событие v1 передаёт статус, а банковская выборка использует `submitted_at`. Credit сравнивает наборы до и после чтения, поэтому даже готовая проекция с неподанным `WITHDRAWN` приводит к чтению из SQL. В `BankSubmissionVisibilityIntegrationTest` сопоставить ответ готовой проекции и SQL на PostgreSQL при совпадении наборов, включая `WITHDRAWN` поданной заявки.

## Условия завершения

Теневой этап закрывается после A01–A08, A10–A13 на кандидате в доступной изолированной среде. A09 и целевые доказательства A11 закрывают допуск к переключению на dev. Для проверки текущего API при выключенном флаге используется часть A09. Точное значение допустимого отставания согласуется по измерению теневого прогона и фиксируется до переключения.

По каждому ID реестр хранит `ожидает`, `в работе`, `пройдено`, `не пройдено` или `заблокировано`. Проверка инфраструктуры и успешная компиляция подтверждают только свои строки. При частичной готовности указываются открытые критерии и условия продолжения.
