# Alpha R2. Граница сервиса оценки

База `830448d6712a32d50bbabff2333f94fda15bea92`. Предыдущий локальный
инкремент служит источником решений и проверок.

| Владелец | Состояние и ответственность |
| --- | --- |
| Credit | Заявка, согласие БКИ, первичная банковская проверка комплекта, опубликованные версии правил и снимок каталога заявки, предодобрение, журнал, решение и предложение. |
| Assessment | Сбор фактов для конкретного цикла, отметки приёма, повтор неполных источников, скоринг и рекомендация по переданному снимку. Собственная БД. |
| Версионированный контракт v1 | Команда и терминальный результат. Идентичность включает поколение, заявку, задачу обогащения, её сохранённую версию, версию правил, версии продуктов и ID кандидата предодобрения. |
| Доставка | Два Kafka topic на поколение. Каждый отправитель пишет свой outbox вместе с изменением в своей БД. Получатель фиксирует приём в БД до подтверждения offset. |

Режим выполнения закрепляется в Credit за задачей обогащения. При включённом
Kafka новый цикл передаётся Assessment. Credit применяет один результат и
сохраняет переходы обогащения и скоринга. Прежний режим по умолчанию
выполняет эти этапы локально. V24 закрепляет локальный режим за открытыми
задачами обогащения, существовавшими до миграции. Переключение режима
касается новых циклов.
Обновление со старого бинарника проводится после остановки старых workers.
Для переноса поколения открытые циклы сначала завершаются в прежнем
поколении или уходят по своему дедлайну на ручное рассмотрение.

Время обогащения ограничивает приём фактов. В удалённом режиме есть
отдельное ограниченное окно доставки результата. При недоступности
Assessment или Kafka по его окончании Credit завершает цикл ручным
рассмотрением. Поздний ответ после закрытия цикла игнорируется. При
отсутствии согласия запрос в БКИ пропускается. Успешные источники текущего
цикла фиксируются вместе с результатом. Публикация выполняется отдельной
очередью, независимо от очереди уведомлений.

| Критерий | Доказательство |
| --- | --- |
| R2-01 | Оба сообщения v1 читаются, несовместимый envelope, неполный результат, чужая версия и поколение отклоняются. |
| R2-02 | Согласие годится только для связанной заявки. При частичном отказе запрашиваются оставшиеся источники, истечение срока переводит заявку на ручную проверку. |
| R2-03 | Факты, правила, выбранный продукт, версии альтернатив и фактически применённое предодобрение воспроизводятся по сохранённому снимку. |
| R2-04 | PostgreSQL подтверждает атомарность входящей записи и outbox, отбрасывание устаревшего lease и единственный эффект при повторе. |
| R2-05 | Отдельные Credit, Assessment, PostgreSQL и реальная Kafka подтверждают обмен, недоступность, рестарт и повтор. |
| R2-06 | Credit V24 и U24 проверены локально. Assessment стартует на чистой БД с собственной V1. Transport выключен по умолчанию, неверные параметры отклоняются. |

Разрешённые маршруты, доступ к снимкам и разведение поколений проверяются
до переключения. Фикстуры контракта подтверждают формат и логику
совместимости. Интеграционный критерий Kafka требует реального брокера.
