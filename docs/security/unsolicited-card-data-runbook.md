# Случайное получение карточных данных

Автор: владелец cabinet-polish. Дата: 24.10.2026.
Статус: инструкция и демонстрационный tabletop; техническое удаление не реализовано.
Область и копии описаны в [документе границ](pci-boundary.md).

## Роли и эскалация

По явному указанию заказчика «мокай» используются следующие учебные назначения.
Они не являются реальными контактами или дежурством эксплуатации.

| Роль | Назначение в репетиции | Канал |
| --- | --- | --- |
| Ответственный за инцидент / ИБ | Дежурный координатор [MOCK] | Учебный канал «PCI tabletop» [MOCK] — запись только метаданных в журнале репетиции |
| Владелец хранения / эксплуатации | Оператор хранения [MOCK] | Тот же учебный канал; решение фиксируется в сценарии, наружу ничего не отправляется |
| Наблюдатель / QA | Исполнитель проверки cabinet-polish | [Журнал приёмки](pci-boundary-acceptance.md), только синтетика |

**До эксплуатации назначить реальных людей и доступный команде канал.** Проверка
мокового взаимодействия не подтверждает доставку эскалации или время реакции людей.

## Порядок действий

1. Прекратить дальнейшее распространение затронутого объекта. Не цитировать сообщение,
   не пересылать файл и не добавлять реквизиты в тикет, screenshot, eval-набор, обычный
   лог или prompt. Сообщить ответственному только object/application/request ID, канал
   и время; ни PAN, ни CVV/PIN, ни фрагмент текста, ни хеш реквизитов.
2. Ответственный за инцидент вместе с владельцем эксплуатации выбирает ограничение
   доступа и дальнейшей передачи. Предметного карантина/скрытия сообщения в приложении
   нет. При необходимости временно ограничивают канал или сервис только по утверждённому
   оператором плану, с учётом влияния на чат, помощник и уведомления. В репетиции сервисы
   не отключают. Нельзя менять права всей компании произвольным SQL.
3. Найти копии по идентификаторам. Проверить исходный объект LOCAL/S3, реестр документов,
   связь с сообщением, неизменяемый аудит, исходный текст, старые объекты после переноса,
   уведомления/outbox/почту, ошибки и cache, выгрузки/PDF, браузерные загрузки, запросы
   модели и backup. Отсутствие на экране или в одной таблице не означает удаления.
   Отчёт содержит места и исход проверки, без содержимого.
4. Согласовать с ИБ немедленное безопасное удаление/редактирование либо защищённую
   обработку по применимым требованиям. Учесть правила расследования и сохранения
   доказательств реального инцидента. Работы выполняет владелец данных/инфраструктуры
   утверждённым способом; массовая очистка разработчиком не допускается.
5. Сохранить ограничения аудита. Сообщения, опубликованные CHAT-вложения и аудит
   неизменяемы. Не отключать append-only triggers и не обходить их owner-учёткой.
   Стандартного API удаления сообщения, карантина или редактирования backup нет.
   Изоляция и устранение таких копий — отдельный открытый пункт ИБ/эксплуатации.
6. Ответить пользователю новым сообщением без реквизитов: «Не присылайте реквизиты
   платёжной карты. Для кредитной заявки они не нужны. Отправьте документ повторно,
   предварительно скрыв эти данные». Не обещать, что прежняя копия удалена, пока
   проверка всех согласованных мест не завершена.
7. Зафиксировать время, идентификаторы, канал, исполнителя, выполненные действия,
   проверенные места и остаток. Для каждой неподдержанной операции записать
   `не поддержано`, роль владельца и следующую задачу. Письменная инструкция не закрывает
   техническое удаление, уничтожение backup или данные у внешнего провайдера.

## Возможности текущего приложения

| Случай | Что доступно | Что нельзя обещать |
| --- | --- | --- |
| Собственный неопубликованный документ/черновик | Штатное удаление в разрешённых состояниях через существующий API | Удаление из ранее сделанных backup, локальных загрузок или старых объектов переноса |
| Отправленное сообщение и опубликованное CHAT-вложение | Проверка доступа по заявке; отдельный банковский аудит | Предметный карантин, редактирование/удаление сообщения и обход неизменяемости вложения |
| Вопрос помощнику / history | Остановить ввод; закрыть контекст; согласовать прекращение передачи модели | Что данные уже не были отправлены и что у модели/в логах нет копий; PCI04 отсутствует |
| Backup, лог, SMTP, скачанный PDF или старый S3-объект | Ограничить доступ средствами эксплуатации после согласования; составить реестр копий | Сквозное удаление одной кнопкой или подтверждение отсутствия данных только по UI |

## Безопасная репетиция

Использовать отдельный `cabinet-polish` и заранее обозначенные синтетические fixtures.
В текстовом сценарии — уникальный учебный маркер без номера; в файловом — безопасное
изображение-заглушка без реквизитов, которое только представляет случай «фотография карты».
Распознавание изображения этим не проверяется. Реальные карточные данные не нужны.

Два прохода выполняют все шаги выше от лица моковых ролей. Проверяют сохранение
синтетического объекта, границы доступа, наличие/отсутствие штатного удаления и
известные места копирования. Payload-логи, trace и screenshots с содержимым сценария
выключены; в отчёт идут ID и исходы. Действия, которых нет в API, отмечают отдельно,
без попыток отключать аудит или удалять базы. Фактический результат репетиции и SHA
публикуются только после проверки в [приёмке](pci-boundary-acceptance.md).

Это не система управления инцидентами, DLP/OCR, API карантина, редактирование
неизменяемого аудита или удаление из backup. Production-применение требует назначения
людей, согласованной процедуры и проверки инфраструктуры конкретного банка.
