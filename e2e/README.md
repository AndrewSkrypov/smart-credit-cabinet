# Сквозные проверки

Playwright проверяет настоящий интерфейс и API работающего стенда. Запускайте на
отдельном демо-стенде: тесты создают компании, завершают активные заявки демо-учёток,
изменяют правила и переключают БКИ. Рабочий или производственный стенд не подходит.
Существующие контейнеры и данные других проектов не очищаются.

```bash
docker compose -p cabinet-e2e up --build --wait --wait-timeout 240
cd e2e
npm ci
npx playwright install chromium
npm run wait
npm run typecheck
npm test
```

На Linux браузеру могут понадобиться системные зависимости:
`npx playwright install --with-deps chromium`. Адрес меняется переменной
`CABINET_URL`, по умолчанию `http://localhost:8080`. Отчёт — `playwright-report/`,
JUnit, снимки ошибок и trace — `test-results/default/` и `test-results/mail/`.
Открыть HTML: `npx playwright show-report playwright-report/default` (или `mail`).
Для локальной проверки установленным Chrome можно задать
`PLAYWRIGHT_CHANNEL=chrome`; CI использует Chromium из фиксированного Playwright.
Фактическая версия браузера печатается в отчёте прогона.

Проекты desktop и mobile выполняются одним воркером: правила и симуляторы общие.
Автоматических повторов упавшего теста нет. Перед сценариями убираются незавершённые
заявки соответствующей демо-компании; собственные активные заявки и общие настройки
восстанавливаются в `finally`. Регистрация получает уникальные ИНН и email.
Для проверки повторяемости выполните `npm test` ещё раз на том же стенде.

После проверки из корня репозитория можно удалить **только этот тестовый стенд**:

```bash
docker compose -p cabinet-e2e down -v
```

Причина отказа берётся из фактического результата API и сверяется с заголовком и
содержимым интерфейса. Селекторы используют роли/подписи; `data-testid` не добавляются.
После редизайна нужно сохранить доступные имена либо согласованно обновить эту таблицу
и тесты. API используется для подготовки отдельных сценариев и дополнительной проверки
состояния; основной клиентский путь выполняется через интерфейс.

Мобильный проект сохраняет профиль Pixel 7 (touch/agent/device scale), но viewport
явно равен **375 × 812 px**. Новые экраны и прежние сценарии проходят на этой ширине.
Без mail почтовые настройки скрыты. Для проверки включённого канала:

```bash
docker compose --profile mail up -d --wait
MAIL_TESTS=1 npm test -- tests/release-notifications.spec.ts tests/release-accounts.spec.ts
```

Команда npm выполняется из `e2e/`. `MAILPIT_URL` по умолчанию `http://127.0.0.1:8025`.
Тест создаёт отдельного получателя, включает настройку в интерфейсе, создаёт реальную
заявку, проверяет письмо через API Mailpit и выключает настройку. Старые подписи сохранены.
Проверки доступа также проходят по реальным ссылкам Mailpit без opt-in, принимают приглашение,
сбрасывают пароль и проверяют 401 старого JWT в identity/credit/engagement. Без почты новый
сотрудник принимает одноразовую ссылку, видит заявку на подписании, получает API403 при
попытке подписать и теряет доступ после отзыва. Профиль проверяет смену пароля и logout-all.
Для этих тестов отключены HTTP traces и снимки ошибок, чтобы не сохранять пароли и ссылки.
При отдельном адресе стенда задайте одинаковый origin в `CABINET_URL` и `PUBLIC_CABINET_URL`.

`release-products.spec.ts` проверяет редактор риска, историю и запрет правки для андеррайтера,
новую ставку после явного согласия старого черновика и сохранение ставки выданного кредита.
Исходные условия восстанавливаются в `finally` новой версией.

Сохранение подтверждается отдельным «ОК»; отмена не пишет версию. При конфликте тест
проверяет сохранность черновика, просмотр действующей версии и подтверждение его замены.
`polish-responsive.spec.ts` отдельно проходит 320/390/640/768/1024/1365 и границы
лендинга, отступы CTA, увеличение его текста и переход по якорю под закреплённой шапкой.
Этот набор запускается один раз в desktop-проекте с явной сменой viewport; три
дублирующих mobile-сценария пропускаются. Остальные сценарии по-прежнему проходят оба проекта.

`release-chat.spec.ts` проверяет переписку клиента и банка, счётчики обеих сторон,
уведомление через колокольчик, PDF с длинным именем и проверкой скачанных байтов,
отображение HTML-подобного текста без разметки и чтение закрытой заявки. Статус,
версия, бизнес-документы и журнал сравниваются до и после переписки.

проверяет 429/Retry-After и понятную ошибку через форму на desktop и 375 px. Пароль
очищается перед снимком; HTTP traces выключены.
