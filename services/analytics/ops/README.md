# Начальная загрузка проекции статусов

Запустите миграции обеих служб и выделите пустую БД Analytics, новый Kafka topic, новый DLQ и новую consumer group. Восстановление Credit требует нового поколения. Первичная загрузка не меняет Credit. Для экспорта достаточно права `SELECT` на `applications(id, version, status)`. Для импорта используйте отдельный профиль владельца БД Analytics с правом создания временных таблиц.

На синтетическом стенде на время экспорта остановите запись заявок. Для загрузки с работающими экземплярами Credit сначала включите транзакционный outbox с новым topic на всех экземплярах. До завершения импорта отключите приём событий Analytics. Импорт можно повторить после запуска потребителя тем же файлом, если требуется подтвердить ранее выполненную загрузку.

Настройте профили libpq через `PGSERVICEFILE` и парольный файл при необходимости. Запустите из корня репозитория.

```bash
export APPLICATION_STATUS_KAFKA_TOPIC=alpha.synthetic.credit.application-status-changed.v1.g123
export CREDIT_SNAPSHOT_SERVICE=alpha-credit-snapshot
export ANALYTICS_SNAPSHOT_SERVICE=alpha-analytics-bootstrap
bash services/analytics/ops/bootstrap-status.sh "$APPLICATION_STATUS_KAFKA_TOPIC" \
    "$PWD/$APPLICATION_STATUS_KAFKA_TOPIC.csv"
```

Скрипт создаёт CSV с идентификатором, версией и статусом заявки. Сохраните напечатанный SHA-256 вместе с именем topic и подтверждённым набором Kafka offsets. При повторе в том же поколении скрипт использует существующий файл и сверяет его SHA-256 с записью в БД. Более новые версии сохраняются.

После восстановления Credit экспортируйте новый файл из восстановленной БД. Запустите публикатор и потребитель с новым topic. Старые строки outbox остаются доступными для аудита и изолированы от этого потока. Потребитель откажется запускаться, если проекция привязана к другому topic. Для возврата к прежнему чтению соблюдайте [процедуру переключения](../../../docs/alpha-pilot-operations.md).
